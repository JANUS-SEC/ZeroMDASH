# 漏洞研究员成长机制分析方法

本框架研究的不是“谁最有名”，而是：一位漏洞研究员如何在特定技术领域中形成可重复的高水平发现能力。候选 CSV 只是抽样框，不是事实来源；所有人物结论都必须回到可核验材料。

## 一、研究问题

每个人最终需要回答八个问题：

1. 进入该领域前，已有的知识、兴趣、环境和约束是什么？
2. 早期做过哪些具体项目、CTF、逆向、审计或工程工作？
3. 哪些反馈回路让其进步加速，例如真实目标、导师、同伴、公开写作或漏洞响应？
4. 哪些转折改变了研究对象、方法或能力上限？
5. 其优势是怎样从一般技能组合成领域专长的？
6. 产出 writeup、工具和演讲如何反过来巩固能力与声誉？
7. 哪些条件属于个人特有、不可简单复制，哪些做法可以迁移？
8. 有哪些相反证据、空白和替代解释？

## 二、六维取证

借鉴 `huashu-nuwa` 的六维并行调研，但把目标从“人物风格蒸馏”改为“成长机制识别”：

| 维度 | 主要材料 | 要提取的成长信号 |
|---|---|---|
| 公开作品 | 博客、writeup、论文、工具、漏洞公告 | 技术难度、方法演化、复盘习惯 |
| 深度对话 | 访谈、播客、AMA、长演讲问答 | 自述的学习路径、失败、导师和选择 |
| 社区活动 | 社交媒体、邮件列表、issue、社区博客 | 同伴网络、持续性、反馈速度、知识分享 |
| 外部视角 | 同事评价、团队介绍、媒体、颁奖材料 | 可交叉验证的优势与盲点 |
| 决策与转折 | 换领域、入职团队、重大项目、披露事件 | 机会、约束、取舍和能力迁移 |
| 时间线 | 教育、工作、漏洞、工具、演讲按时间排列 | 先后关系、滞后效应、阶段边界 |

六个 Agent 可以并行，但不得互相读取结论，以减少锚定效应。综合 Agent 只能在六份材料落盘后运行。

## 三、证据与推断纪律

证据优先级：

1. 当事人的同期作品、代码、writeup、演讲和可核验漏洞记录；
2. 当事人的回顾性长访谈；
3. 同事或组织的一手叙述；
4. 权威二手报道；
5. 聚合页面、搜索摘要和无来源转述，只能作为线索。

每个事实或机制必须标注为：

- `documented`：来源直接支持；
- `reported`：他人陈述，尚未由当事人或作品验证；
- `inferred`：研究者基于多个事实作出的解释；
- `unknown`：材料不足，不应补全。

不要把演讲年份当成掌握技能的年份，不要把加入知名团队当成因果解释，也不要从当前成就倒推早期动机。保留时间矛盾、领域矛盾和当事人自述与外部评价之间的张力。

## 四、成长机制判定

一个“成长机制”至少满足下列三项中的两项，才能进入主结论：

1. **重复出现**：在不同年份或不同材料中可观察；
2. **生成力**：能解释后来至少两项行为或成果；
3. **区分度**：不是“努力、聪明、热爱”等对任何人都适用的空话。

综合 Agent 为每个机制输出：起点条件、行为/练习、反馈来源、中间能力、可观察成果、证据、置信度、替代解释、可迁移边界。因果语言仅在证据足够时使用，否则写成“可能促成”或“与……一致”。

## 五、独立复核

复核 Agent 与综合 Agent 隔离，重点检查：

- 来源是否真的支持附近的句子；
- 是否混淆相关性、时间先后和因果；
- 是否有幸存者偏差、名气偏差、组织光环或英语资料偏差；
- 是否遗漏失败、停滞、偶然性和资源优势；
- 建议是否错误地把个人特有条件包装成普适路径。

复核总分 100：证据可追溯 25、因果克制 25、时间线一致 15、替代解释 15、领域解释力 10、可迁移边界 10。复核只有 `pass` 和 `revise` 两种结果；低于 75 分或存在关键事实错误时必须为 `revise`。

`revise` 必须携带具体理由并回流 `targeted-research`。该节点把问题分成缺少证据、错误来源、身份/时间线错误和过度推断，定向补证或标记旧证据无效，然后重新综合、重新复核。最大循环次数由 CLI 的 `--max-revisions` 控制，默认 3。达到上限仍未通过时只生成审计草稿，不生成最终报告，也不进入跨人物比较。

## 六、跨人物比较

只比较通过复核的人物。先按领域、时代、组织环境和职业阶段分层，再寻找模式；不得用会议次数或关注者数量作为成长能力代理指标。跨案例结果分为：

- 多案例共同机制；
- 领域特定机制；
- 互相矛盾但都成立的路径；
- 暂时无法比较的证据缺口。

最终产物应明确区分“描述性发现”“机制假设”和“可执行建议”。
